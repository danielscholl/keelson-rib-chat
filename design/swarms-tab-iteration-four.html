keelson-rib-chat · swarms surface · design, iteration four

A Swarms tab you can watch

The fourth pass puts a live swarm on the page instead of behind a drawer, shows what the agents are saying and who is working this minute, says whether the budget will last, and opens any agent, run or question in a side inspector while the page stays. Everything but one timeline strip renders on the canvas Keelson 0.117 ships; appendix C bounds that one addition, and appendix F orders the slices.

Today, watching a live swarm means opening a centered drawer that covers the index, reading nine sections of equal weight, opening a second drawer for the record, and switching to ClickClack to learn what the agents actually said. The board reports events (turn 3 ok · 46 s · 1 new), not words. The budget says what is spent and not whether it will last. The agent bench is a grid of monospace cards with ghost seats, which on a one-agent swarm is one card and four fifths of empty row. Pull requests that writers open in write mode are on the summary and nowhere on the tab. Four verbs (Open the report, Read the conclusion, Open the record, Read the full log) name four reading places.

This pass composes a live swarm's cockpit on the tab page itself: a state line derived from the record, the requests, a budget strip that forecasts the turn budget against the clock, the agents as a host-drawn map beside the newest messages, the work produced so far, and one strip of verbs. Clicking an agent, a run or a question opens a side inspector that docks beside the page and swaps in place on the next click; the page never leaves view. Ended swarms keep their drawer board, which gains writers' pull requests and sheds sections the record already draws. To draw the feed, the rib keeps the newest 20 messages on the summary; to draw the map, it uses the graph section Keelson 0.116 added. ClickClack becomes plumbing on the tab: the channel is reached through quiet transcript links and the server through one row at the foot of the page, and no card, title or button names it. One Keelson addition is specified and bounded in appendix C: a timeline board section, so the record's lanes can sit on the page too.

The tab still does not mirror the channel, pause a swarm, approve a gate from the page, or change an agent's role; those stay with ClickClack, the run drawer and the engine. Selection on the page is one state shared by every viewer of the tab, as the Beads tab's inspector already is. The record page stays centered, because the host docks only structured views. Spend stays in tokens. Nothing here changes routing, limits or what an agent may do.

The page is the cockpit

The host holds one canvas drawer at a time. A centered drawer is modal and covers the tab; a side drawer docks beside the page, is not modal, and is replaced by the next one opened. Only a structured view can dock; html and markdown documents always open centered. Those three rules set the layout: a thing the operator watches continuously belongs on the page, and a thing the operator drills into belongs in the side drawer. Today the live board is in the first kind of drawer, so watching a swarm means reopening it after every drill-down.

The index board therefore composes a live swarm's cockpit inline, under Needs you and above the ended rows, the way the Beads tab composes its Overview, Now and wave map on one page. With two or more live swarms, a tabs actions strip above the cockpit picks which one is expanded and the others fold to one running card each; the choice is a select-swarm action the rib records and composes into the next frame, so it is shared by every viewer of the tab. The cockpit's own sections are the host's board vocabulary, and none of them is new to the rib except the map and the message feed.

Everything above the ended rows is one board frame. The cockpit's map and feed are a two-column section; at a narrow width the host stacks them, map first.

The state line

The cockpit's first sentence says where the swarm stands, and it is derived, never typed by an agent, so it claims only what the record shows. It reads left to right from the most consequential fact: a request first, then turns in flight, then agents waiting, then what a run waits at, then the newest event when nothing else is true. Each clause names its actor and its time. The index's running card uses the same line, so the two agree.

A budget that forecasts

The summary already keeps turns started per minute over the last thirty minutes. The rib reads the last five minutes of it as the pace and divides the turns left by that pace; the result is when the turn budget runs out. Set beside the wall clock, that gives one of three readings, and the Turns tile carries it as its delta, with the direction glyph the host draws and a tone that says whether the reading is good. A pace under one turn in five minutes is reported as no pace, not as infinite time.

ReadingDelta textTone
Turns run out before the clock▼ 8 left · at 1.5 a minute they run out about 11:56, before the clockwarn

No pace in five minutes→ 22 left · no turn in 5 minnone; the quiet request says more when a gate is involved

The forecast is a projection of the last five minutes and the tile says so in its sub. It never changes what the engine does; it tells the operator whether to raise the budget on the next run or to message the lead now.

Agents as a map, and the inspector

The bench becomes a map. The host's graph section ranks nodes in columns and draws edges between them, and since 0.116 a node carries a tone, a sublabel and badges, so the agents keep the identity colors the record gives them. The rib ranks the operator at zero, the lead at one, workers at two, runs at three, and labels the columns. A node's sublabel is its turns against the cap and its status; a run's is its status and steps. Edges are the record's who woke whom: a spawn as a solid edge whose label counts the turns the spawner went on to wake, a wake between peers as a labelled edge, a question to the operator dashed, and a run's updates to the lead labelled as such. Before 0.116 a node took no tone, which kept the map on the record page.

Clicking a node is a select-agent action. The rib composes the agent's inspector board and answers with open-canvas, placement side, so the inspector docks beside the page and the next click swaps it. The inspector is designed for 520 pixels and answers what the operator asks about one agent: what it is doing, what it has said, what it has made, what it has cost, and how to reach it. Message @agent posts in the channel as the operator with the agent mentioned, which the router turns into a wake; the field's placeholder says so and that the wake spends a turn. A writer's inspector names its worktree and branch and links its draft pull request. An ended swarm's agent inspector is the same board without the live clock and the composer.

The side drawer is not modal: the page stays live and clicking another node swaps the inspector. Opening the record or the report replaces it with a centered drawer, since those are html.

The conversation on the tab

The rib ingests every message in the channel to route it, so it already holds each message body as it arrives. It keeps the newest 20 as recent on the summary: id, time, author (an agent id or operator), the first 200 characters of the body, the thread root when the message is a reply, and the message's kind when the rib knows it (a question to the operator, a report, the conclusion). The cockpit shows the newest eight as Conversation: the author as a chip in the agent's identity tone or you, a reply marked with ↳, the time at the end, and each row carrying its thread as its link, with no text naming where the thread lives. One quiet line under the rows counts the rest and links the transcript. The agent inspector filters the same list to one author.

The feed changes with every message, so the board republishes on a new message change kind inside the publisher's existing window; a burst of posts in one second is one frame. The 20-message buffer is the board's, not a transcript: the status tools leave it out as they leave out turn spans, and chat_swarm_transcript remains the way to read the channel in full. Message text is agent and operator text and reaches the board as field text, which the host renders without markup, as the activity feed's text does today.

What the swarm has produced

Today the runs section appears only when the launch named workflows, and writers' pull requests appear nowhere. Produced so far replaces it and lists every artifact a swarm can make, in the order they land: the report once published (title, size, Open the report), each dispatched run as today (purpose, branch, evidence strip of worktree, pull request and CI, took, and the error gist for a failed one, with Open run on the row and each gate answer under it), and each writer's draft pull request from prs with the writer's chip, its branch and the CI verdict the rib reads, linking the pull request. After the swarm ends, any worktree the rib left on disk is a row with its path and the reason it was kept, so the operator knows what to clean up. When the swarm can produce nothing yet, the section says what the lead may start or who may write.

Requests beside the page

The ladder, its pills and its first verbs are unchanged. What changes is where a request opens. Read question opens the question inspector at the side rather than the markdown reading pane in the center, so the operator reads the question with the feed and the map still in view, and replies from the same drawer. A reviewing card opens the gate inspector the same way. Review plan and Answer still open the run drawer, since only it carries the approval composer. Start ClickClack and Message the lead stay inline. The reading pane remains for the conclusion, a refused draft and the full task, where a long markdown document is the right form.

The channel and the server

ClickClack is where the agents talk and the rib's bus; it is not where the operator works. Today it is the most visible word on the tab: a footer card with its own pill and four verbs, a link line on every request card, a channel field on the outcome card, a row in About, and a title on the feed. Each of those invites the operator out of the tab into a chat client the rib does not control, and the tab's own reading surfaces lose the argument. This pass keeps every way to reach the channel and removes every piece of chrome that promotes it.

The rule is that the channel is reached through the thing being read, never named beside it. A message row links its thread. The conversation's count line links the transcript. A question or gate inspector carries its thread as a small link. About keeps one transcript row. Nothing else on the tab says ClickClack. The footer card becomes one muted line at the foot of the page naming the server, its address and mode, with a single Manage link that opens a server inspector at the side; Start, Stop, Reset with its typed confirm, and the log live there. The line turns into a request only through the ladder's connection kind, which already says ClickClack stopped answering and offers Start ClickClack, since that is the one moment the server is the operator's problem. The managed server still starts itself with the first swarm, so a stopped server on an idle tab is not a warning.

One Keelson addition: a timeline section

The record's timeline is the one drawing that shows a swarm's rhythm: who worked when, where the gaps are, when a gate opened and how long it waited. It lives on an html page because the board has no primitive for spans on lanes; the chart section plots values and caps at six series. This pass proposes a timeline board section so the same lanes can sit on the cockpit, host-drawn and themed, with the now rule ticking between frames the way clocks do. The Beads wave map took the same route with the graph section: an html region first, then the primitive once the host had it. The cockpit ships without it and the record stays the drawing until the host adds it; the section then lands under the budget strip in one rib change.

What the section would take: lanes with a label and a tone, spans with a lane, a start, an optional end, a tone and a title, marks with a lane, a time, a glyph and a title, and a window with a start and an end or a clock. Appendix C gives the shape and the caps.

Validation

The index, the cockpit, the inspectors and the ended board are pure functions of the swarm summary and the selection, so the builders are tested against fixture summaries, one per state the design names: a running swarm with no request and one with each request kind; a swarm with two busy agents and a waiting one; a run paused at a gate a peer reviews; a write swarm with a draft pull request and a kept worktree; each of the five forecast readings, from a pace fixture; two live swarms with a selection; an ended swarm with a report, one with a conclusion only, one stopped, one out of turns; and the bounds, 12 agents and 200 turns, for the map and the feed. Each frame passes expectView(key, kind), and the index stays under 48 KB with the cockpit and 20 recent messages, which the fixture at the bounds checks.

The feed is tested at the engine: 50 messages posted in one second produce one recent buffer of 20 and one board frame within the publisher's window; a message with markup reaches the board as text; the status tools' output carries no recent buffer. The inspector is tested at the action: a select-agent for an unknown id is refused; one for an agent composes its key before the open-canvas reply; a message to an agent posts with the mention and the activity names it. The forecast is tested on its rules: fewer than one turn in five minutes gives the no-pace reading, and a pace that runs out after the clock gives the clock-first reading.

The page is rendered from the bounds fixture with headless Chrome in both themes at 1200 and 640 pixels, and the screenshots go in the pull request; at 640 the two-column section stacks and the map's narrow fallback shows. The live smoke test asserts that a scripted swarm's cockpit appears on the index at start, that its feed shows the lead's first post, and that clicking the lead's node opens the inspector at the side. The chat docs corpus and the tab guide restate the page and change with it.

C · Keelson-side change: the timeline section

One addition to the board vocabulary, additive like the graph section. The host draws the lanes, the ticks, the spans and the marks from the design tokens, re-ticks the now rule from the window's clock between frames, and offers the same narrow fallback the graph has: a list of spans per lane.

kind: "timeline"
title?: string
window: { from: iso, to: iso } | { from: iso, clock: { until: iso } }
lanes: [{ id, label, tone?: id-* | brand | neutral | info, group?: string }]   // ≤ 12
spans: [{ lane, from: iso, to?: iso, tone?, hatched?: boolean, title }]        // ≤ 400
marks: [{ lane, at: iso, glyph: 1 char, title }]                               // ≤ 200
legend?: string

An optional second change, smaller: let open-canvas dock an html document at the side. It would let the record sit beside the page; nothing in this pass depends on it.
